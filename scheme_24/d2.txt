Так, твій `OracleDBManager` можна доопрацювати без зміни сигнатур наявних методів `query()`, `queryMany()` та `execute()`. Це важливо, оскільки вони вже використовуються в інших контролерах API.

На скріншотах видно, що менеджер підтримує пул з'єднань і режим звичайного підключення, а `query()` та `queryMany()` самостійно отримують і звільняють з'єднання. Саме тому їх не варто послідовно викликати для збереження JSON та індексованих об'єктів: кожен виклик може працювати в окремій транзакції.

Найкраще рішення — додати новий метод `withTransaction(dbName, callback)`, залишивши старі методи без змін.

Він отримуватиме одне з'єднання, передаватиме його всім SQL-операціям, а наприкінці виконуватиме один `COMMIT` або `ROLLBACK`.

Підготував доопрацювання саме для твоєї реалізації `OracleDBManager`, з урахуванням пулу з'єднань, `autoCommit: true` та наявних методів.

OracleDBManager — підтримка транзакцій

TXT, 231 рядок — код нових методів, приклад сервісу збереження та перевірки

## Що саме додаємо

У клас `OracleDBManager` додаються лише два методи:

```
getTransactionConnection(dbName)
withTransaction(dbName, callback)
```

Тоді збереження документа виглядатиме так:

```
await OracleDBManager.withTransaction(
  dbName,
  async (tx) => {
    await tx.execute(sqlSnapshot, snapshotParams);

    await tx.executeMany(sqlObjects, objectParams);

    await tx.executeMany(sqlAttributes, attributeParams);

    // COMMIT автоматично після успішного callback
  }
);
```

Якщо будь-який SQL-запит завершується помилкою, менеджер виконає `ROLLBACK` для всіх операцій цієї транзакції.

Наявні `query()`, `queryMany()` та `execute()` залишаються без змін.

### Особливість твого менеджера

На скріншотах видно, що в тебе є два режими підключення: через pool і через спільне з'єднання.

Для транзакцій я рекомендую використовувати окреме з'єднання з pool, щоб два одночасні HTTP-запити не змішували свої транзакції. Саме такий варіант реалізований у TXT.

Також враховано, що твій `defaultOptions.autoCommit = true`: новий транзакційний метод примусово встановлює `autoCommit: false`, не змінюючи поведінку старих методів.

Наступний крок — підключити `withTransaction()` до твого `documentSaveService`, щоб JSON, `DOC_OBJECT`, `DOC_OBJECT_ATTRIBUTE` і `DOC_OBJECT_LINK` оновлювалися атомарно.
