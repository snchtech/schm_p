Щоб відкрити збережену схему, потрібно виконати зворотний процес:

Oracle 21c → Node.js API → Next.js → Zustand Store → Konva.

Оскільки твій редактор побудований на Zustand, не потрібно вручну створювати кожен NODE, EDGE чи ZVT після завантаження. Достатньо відновити їхні дані у Zustand, і React + Konva автоматично перемалюють схему.

## 2. SQL для отримання JSON із Oracle

Використовуємо таблицю `DOC_SNAPSHOT`, де кожен запис прив'язаний до конкретної версії документа.

```
SELECT
    s.SNAPSHOT_JSON,
    s.SAVE_REVISION,
    v.STATUS_CODE
FROM DOC_SNAPSHOT s
JOIN DOC_VERSION v
    ON v.ID = s.DOC_VERSION_ID
WHERE s.DOC_VERSION_ID = :versionId
```

Так можна відкрити і `DRAFT`, і `STABLE`, і `ARCHIVED`. Але редагувати дозволяємо лише DRAFT.

## 3. Node.js API — отримання snapshot

Приклад для Express і `node-oracledb`:

```
router.get(
  "/schemes/:versionId/snapshot",
  async (req, res) => {
    try {
      const { versionId } = req.params;

      const result = await OracleDBManager.query(
        "main",
        `
          SELECT
              s.SNAPSHOT_JSON,
              s.SAVE_REVISION,
              v.STATUS_CODE
          FROM DOC_SNAPSHOT s
          JOIN DOC_VERSION v
              ON v.ID = s.DOC_VERSION_ID
          WHERE s.DOC_VERSION_ID = :versionId
        `,
        { versionId }
      );

      if (!result.rows.length) {
        return res.status(404).json({
          message: "Snapshot не знайдено"
        });
      }

      const row = result.rows[0];

      // Якщо CLOB повернувся як потік, його треба прочитати.
      // Налаштування outFormat залежить від OracleDBManager.
      const raw = row.SNAPSHOT_JSON;

      const snapshot =
        typeof raw === "string"
          ? JSON.parse(raw)
          : raw;

      return res.json({
        snapshot,
        saveRevision: row.SAVE_REVISION,
        status: row.STATUS_CODE
      });

    } catch (error) {
      console.error(error);
      return res.status(500).json({
        message: "Помилка завантаження схеми"
      });
    }
  }
);
```

Тут необхідно додати перевірку прав користувача на читання документа. Для `node-oracledb` бажано налаштувати отримання CLOB як рядка; якщо драйвер повертає `Lob`, його потрібно асинхронно прочитати перед `JSON.parse`.

## 4. Zustand — метод відновлення схеми

У твій store додаємо окремий метод `loadSnapshot`.

```
import { create } from "zustand";

export const useSchemeStore = create((set) => ({
  nodes: [],
  edges: [],
  zvt: [],
  branches: [],
  specifications: [],

  loadSnapshot: (snapshot) => {
    set({
      nodes: snapshot.nodes ?? [],
      edges: snapshot.edges ?? [],
      zvt: snapshot.zvt ?? [],
      branches: snapshot.branches ?? [],
      specifications: snapshot.specifications ?? [],
    });
  },
}));
```

Це демонстраційний приклад. У твоєму реальному store потрібно відновлювати всі поля, які входять до документа: стилі, шари, параметри ЗВТ, точки зламу, прив'язки, примітки, таблиці, графічні файли тощо.

Важливо також не затирати методи Zustand, не записувати в JSON функції, Konva-об'єкти чи React refs і не залишати об'єкти попередньої схеми після завантаження нової.

## 5. Next.js — функція відкриття схеми

```
import { useSchemeStore } from "@/store/useSchemeStore";

export async function openScheme(versionId) {
  const response = await fetch(
    `/api/schemes/${encodeURIComponent(versionId)}/snapshot`
  );

  if (!response.ok) {
    throw new Error("Не вдалося завантажити схему");
  }

  const data = await response.json();

  // Відновлюємо дані редактора
  useSchemeStore.getState().loadSnapshot(
    data.snapshot
  );

  return {
    saveRevision: data.saveRevision,
    status: data.status
  };
}
```

Після виклику:

```
await openScheme("version-004");
```

Zustand оновить дані, а компоненти React-Konva, які підписані на відповідні поля store, перемалюються.

## 6. Що робити зі STABLE і DRAFT

| Статус   | Відкриття | Редагування | Збереження |
| -------- | --------- | ----------- | ---------- |
| DRAFT    | Так       | Так         | Так        |
| STABLE   | Так       | Ні          | Ні         |
| ARCHIVED | Так       | Ні          | Ні         |

У Next.js можна встановлювати режим редактора:

```
const readOnly = data.status !== "DRAFT";
```

Але це лише обмеження інтерфейсу. API також повинен забороняти збереження STABLE та ARCHIVED.

## 7. Дуже важливий момент для твого проєкту

У тебе є складні графічні об'єкти: `EDGE`, `ZVT`, `ZVT_BRANCH`, orthogonal connectors, точки зламу, прив'язки до інших об'єктів.

Тому після завантаження потрібно перевірити, що:

- ID об'єктів і зв'язків залишилися незмінними.
- Геометрія та координати повністю відновилися.
- Всі anchor points і посилання `attachedTo` коректні.
- Параметри стилів, шарів і таблиць специфікацій збережені.
- Алгоритми побудови ліній використовують сумісні версії.

Якщо частина геометрії обчислюється динамічно, її потрібно відновити детерміновано з даних snapshot. Не варто без потреби запускати функції, які створюють нові ID або змінюють структуру об'єктів.

Моя рекомендація: реалізувати у Zustand дві симетричні функції:

```
exportSnapshot()
loadSnapshot(snapshot)
```

Перша формує серіалізований JSON для Oracle, друга відновлює з нього повний стан редактора.

Тоді можна буде перевірити весь цикл:

Створити схему → Зберегти → Закрити редактор → Відкрити → Отримати точно той самий графічний стан.

І цей механізм однаково працюватиме для схем обладнання, будівель, планів поверхів та інших типів документів.
