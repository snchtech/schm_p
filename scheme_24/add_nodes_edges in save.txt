Для твоєї поточної реалізації я рекомендую не створювати другий запит із frontend для збереження `nodes` та `edges`.

Ти вже формуєш JSON через `canvasController.prepareAndValidateSnapshot()` і передаєш його на API. Тому правильніше розширити наявний обробник `PUT /api/documents/:versionId/snapshot`, щоб він в одній транзакції записував:

- `DOC_SNAPSHOT` — повний JSON для відновлення Canvas;
- `DOC_OBJECT` — індексовані `NODE` та `EDGE`;
- `DOC_OBJECT_ATTRIBUTE` — атрибути для пошуку й інформаційних карток;
- `DOC_OBJECT_LINK` — зв'язки між об'єктами, якщо вони явно визначені в `edge`.

При цьому в раніше погодженій схемі `DOC_OBJECT` не обов'язково має колонку `OBJECT_JSON`. Тому не будемо припускати, що вона існує: повний JSON залишається в `DOC_SNAPSHOT`, а в індексовані таблиці потрапляють тільки потрібні поля.

Нижче — приклад під твої Express-контролери, `req.locals.dbName` і Zustand.

## 2. Frontend — нічого додатково відправляти не потрібно

Якщо твій `buildSnapshot()` повертає таку структуру:

```
{
  schemaVersion: 1,
  nodes: [...],
  edges: [...]
}
```

залишаємо один виклик:

```
export const saveDocument = async (
  versionId,
  saveRevision
) => {
  const snapshot =
    canvasController.prepareAndValidateSnapshot();

  return fetchData(
    `/api/documents/${versionId}/snapshot`,
    "PUT",
    {
      snapshot,
      saveRevision
    }
  );
};
```

У твоєму `fetchData()` потрібно перевірити, що третій аргумент справді передається як JSON-тіло запиту.

Важливо: твоя поточна функція `prepareAndValidateSnapshot()` формує нові об'єкти з вибраними полями. Для атрибутів обладнання необхідно переконатися, що потрібні дані не губляться під час цього перетворення.

## 4. Як записати NODE та EDGE в DOC_OBJECT

За нашою попередньою структурою ключем є:

`(DOC_VERSION_ID, OBJECT_ID)`

Використовуємо такі колонки:

```
INSERT INTO DOC_OBJECT (
    DOC_VERSION_ID,
    OBJECT_ID,
    OBJECT_TYPE,
    OBJECT_SUBTYPE,
    LABEL,
    EXTERNAL_OBJECT_ID,
    UNIT_ID,
    SEARCHABLE_TEXT,
    PARENT_OBJECT_ID,
    IS_DELETED
)
VALUES (
    :versionId,
    :objectId,
    :objectType,
    :objectSubtype,
    :label,
    :externalObjectId,
    :unitId,
    :searchableText,
    :parentObjectId,
    0
)
```

Для першої реалізації можна використовувати повну заміну індексованих NODE та EDGE при кожному Save, а не обчислювати зміни кожного об'єкта.

Це відповідає твоїй моделі пакетного збереження.

Однак видаляти потрібно лише дані поточної DRAFT і лише відповідні типи об'єктів. Порядок видалення має враховувати зовнішні ключі.

## 5. Підготовка даних для Oracle

Створимо `documentIndexMapper.js`.

```
export function mapObjects(snapshot, versionId) {
  const nodes = snapshot.nodes ?? [];
  const edges = snapshot.edges ?? [];

  return [
    ...nodes.map(node => ({
      versionId,
      objectId: node.id,
      objectType: "NODE",
      objectSubtype: node.type ?? null,
      label: node.data?.label ?? node.label ?? null,
      externalObjectId:
        node.data?.externalObjectId ?? null,
      unitId: node.data?.unitId ?? null,
      searchableText:
        node.data?.label ?? node.label ?? null,
      parentObjectId: null
    })),

    ...edges.map(edge => ({
      versionId,
      objectId: edge.id,
      objectType: "EDGE",
      objectSubtype: edge.kind ?? null,
      label: edge.label ?? null,
      externalObjectId: null,
      unitId: null,
      searchableText: edge.label ?? null,
      parentObjectId: null
    }))
  ];
}
```

Це приклад мапінгу. Точні шляхи до `externalObjectId`, `unitId`, `label` потрібно встановити за структурою реальних об'єктів.

## 6. Атрибути — DOC_OBJECT_ATTRIBUTE

Наприклад, для вузла обладнання ти хочеш індексувати:

- найменування;
- тип обладнання;
- зовнішній ідентифікатор;
- ширину та висоту;
- координати X/Y.

Таблиця атрибутів:

| OBJECT_ID | ATTRIBUTE_CODE | VALUE_TEXT       | VALUE_NUMBER |
| --------- | -------------- | ---------------- | ------------ |
| node-001  | EQUIPMENT_TYPE | PUMP             |              |
| node-001  | POS_X          |                  | 150          |
| node-001  | POS_Y          |                  | 200          |
| node-001  | WIDTH          |                  | 100          |
| edge-001  | CONNECTOR_TYPE | orthogonal-elbow |              |

Приклад функції:

```
export function mapAttributes(snapshot, versionId) {
  const attributes = [];

  function add(objectId, code, value) {
    if (value === null || value === undefined) {
      return;
    }

    attributes.push({
      versionId,
      objectId,
      attributeCode: code,
      valueText:
        typeof value === "string" ? value : null,
      valueNumber:
        typeof value === "number" &&
        Number.isFinite(value)
          ? value
          : null,
      valueDate: null
    });
  }

  for (const node of snapshot.nodes ?? []) {
    add(node.id, "POS_X", node.position?.x);
    add(node.id, "POS_Y", node.position?.y);
    add(node.id, "WIDTH", node.data?.width);
    add(node.id, "HEIGHT", node.data?.height);
    add(node.id, "EQUIPMENT_TYPE", node.type);
  }

  for (const edge of snapshot.edges ?? []) {
    add(edge.id, "CONNECTOR_TYPE", edge.connectorType);
    add(edge.id, "PATH_TYPE", edge.pathType);
  }

  return attributes;
}
```

SQL:

```
INSERT INTO DOC_OBJECT_ATTRIBUTE (
    DOC_VERSION_ID,
    OBJECT_ID,
    ATTRIBUTE_CODE,
    VALUE_TEXT,
    VALUE_NUMBER,
    VALUE_DATE
)
VALUES (
    :versionId,
    :objectId,
    :attributeCode,
    :valueText,
    :valueNumber,
    :valueDate
)
```

Не потрібно записувати абсолютно всі властивості вузла в атрибути. Тільки ті, за якими планується пошук, фільтрація, формування звітів або робота інформаційних карток.

## 7. Збереження через OracleDBManager

У твоєму `OracleDBManager` зараз є:

```
OracleDBManager.query(dbName, sql, params)
```

Але для цього сценарію потрібно отримати одне з'єднання, на якому виконуються всі операції.

Нижче приклад сервісу. Він передбачає, що `getConnection(dbName)` повертає `node-oracledb Connection`, а `saveSnapshotRow()` уже реалізує запис JSON і перевірку `SAVE_REVISION`.

```
import OracleDBManager from
  "../db/OracleDBManager.js";

import {
  mapObjects,
  mapAttributes
} from "./documentIndexMapper.js";

export async function saveDocumentData({
  dbName,
  versionId,
  snapshot,
  saveRevision,
  userId
}) {
  const connection =
    await OracleDBManager.getConnection(dbName);

  try {
    // Перевірка доступу, DRAFT та блокування версії
    await assertEditableDraft(
      connection,
      versionId,
      userId
    );

    const objects = mapObjects(snapshot, versionId);
    const attributes = mapAttributes(
      snapshot,
      versionId
    );

    validateIndexedData(objects, attributes);

    // Зберігаємо повний JSON
    const newRevision = await saveSnapshotRow(
      connection,
      versionId,
      snapshot,
      saveRevision
    );

    // Спочатку залежні записи
    await connection.execute(
      `DELETE FROM DOC_OBJECT_ATTRIBUTE
       WHERE DOC_VERSION_ID = :versionId
         AND OBJECT_ID IN (
           SELECT OBJECT_ID
           FROM DOC_OBJECT
           WHERE DOC_VERSION_ID = :versionId
             AND OBJECT_TYPE IN ('NODE', 'EDGE')
         )`,
      { versionId },
      { autoCommit: false }
    );

    // Аналогічно видаляємо залежні DOC_OBJECT_LINK,
    // які стосуються NODE/EDGE.

    await connection.execute(
      `DELETE FROM DOC_OBJECT
       WHERE DOC_VERSION_ID = :versionId
         AND OBJECT_TYPE IN ('NODE', 'EDGE')`,
      { versionId },
      { autoCommit: false }
    );

    if (objects.length) {
      await connection.executeMany(
        `INSERT INTO DOC_OBJECT (
          DOC_VERSION_ID, OBJECT_ID, OBJECT_TYPE,
          OBJECT_SUBTYPE, LABEL, EXTERNAL_OBJECT_ID,
          UNIT_ID, SEARCHABLE_TEXT, PARENT_OBJECT_ID,
          IS_DELETED
        ) VALUES (
          :versionId, :objectId, :objectType,
          :objectSubtype, :label, :externalObjectId,
          :unitId, :searchableText, :parentObjectId, 0
        )`,
        objects,
        { autoCommit: false }
      );
    }

    if (attributes.length) {
      await connection.executeMany(
        `INSERT INTO DOC_OBJECT_ATTRIBUTE (
          DOC_VERSION_ID, OBJECT_ID, ATTRIBUTE_CODE,
          VALUE_TEXT, VALUE_NUMBER, VALUE_DATE
        ) VALUES (
          :versionId, :objectId, :attributeCode,
          :valueText, :valueNumber, :valueDate
        )`,
        attributes,
        { autoCommit: false }
      );
    }

    // Тут синхронізуємо DOC_OBJECT_LINK
    // після вставки всіх об'єктів.

    await connection.commit();

    return {
      success: true,
      saveRevision: newRevision,
      indexedObjects: objects.length,
      indexedAttributes: attributes.length
    };
  } catch (error) {
    await connection.rollback();
    throw error;
  } finally {
    await connection.close();
  }
}
```

Це каркас інтеграції, а не завершений сервіс. Функції `assertEditableDraft`, `saveSnapshotRow` і `validateIndexedData` потрібно підключити до реалізованої логіки. Також необхідно перевірити всі зовнішні ключі перед видаленням об'єктів: інші типи об'єктів можуть посилатися на NODE або EDGE.

Для великих схем варто додати `bindDefs` до `executeMany()` та пакетну обробку.

```
FROM DOC_OBJECT_ATTRIBUTE
WHERE DOC_VERSION_ID = :versionId
  AND OBJECT_ID = :objectId
ORDER BY ATTRIBUTE_CODE
```

Знайти обладнання за зовнішнім ID у всіх актуальних STABLE:

```
SELECT
    d.ID AS DOCUMENT_ID,
    d.TITLE,
    o.OBJECT_ID,
    o.LABEL,
    o.EXTERNAL_OBJECT_ID
FROM DOC_OBJECT o
JOIN DOC_VERSION v
  ON v.ID = o.DOC_VERSION_ID
JOIN DOC_RESOURCE d
  ON d.ID = v.DOC_RESOURCE_ID
WHERE v.STATUS_CODE = 'STABLE'
  AND o.OBJECT_TYPE = 'NODE'
  AND o.IS_DELETED = 0
  AND o.EXTERNAL_OBJECT_ID = :externalId
```

## 9. Що робити з DOC_OBJECT_LINK

У твоїх `edges` уже є складні властивості `start.attached`, `end.attached`, `route`, `geometry` та інші.

Тут потрібно окремо визначити, які з них означають логічний зв'язок між двома NODE, а які лише описують геометрію лінії.

Я б не створював записи `DOC_OBJECT_LINK` автоматично з будь-якого `attached`, доки не встановимо точну структуру цих полів.

Найважливіше для наступного кроку: у твоїй системі потрібно зберігати індексовані NODE, EDGE та атрибути синхронно з JSON. Але перед фінальною реалізацією варто уточнити структуру двох реальних об'єктів із Zustand і зовнішні ключі `DOC_OBJECT_LINK`.

Тоді зможемо написати готовий `documentSaveService.js`, який працюватиме з твоїм `OracleDBManager`, без умовних функцій і без ризику видалення пов'язаних об'єктів.
