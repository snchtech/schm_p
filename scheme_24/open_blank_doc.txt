Для цього потрібно передбачити два сценарії у функції `openDocument()`:

- Snapshot є в Oracle — завантажуємо JSON і відновлюємо `nodes`, `edges`.
- Snapshot немає — очищаємо попередню схему в Zustand і відкриваємо порожній Canvas.

Важливо: відсутність Snapshot — це не помилка, якщо документ уже створений у `DOC_RESOURCE` та `DOC_VERSION`, але користувач ще не зберігав його вміст.

## 1. Backend — повертаємо інформацію про відсутність Snapshot

У `documentController.js` після SQL-запиту:

```
if (!result.rows.length) {
  return res.status(200).json({
    exists: false,
    snapshot: null,
    saveRevision: 0,
    message: "Документ ще не має збереженої схеми"
  });
}
```

Якщо запис є:

```
return res.status(200).json({
  exists: true,
  snapshot: parsedSnapshot,
  saveRevision: row.SAVE_REVISION,
  status: row.STATUS_CODE
});
```

При цьому сам `DOC_VERSION` потрібно перевіряти окремо. Якщо документа або версії не існує, сервер має повертати `404`, а не порожню схему. Також обов'язково перевіряємо права доступу.

## 2. Frontend — функція очищення Canvas

У твоєму `useCanvasStore.js` можна додати метод:

```
clearCanvas: () =>
  set({
    nodes: [],
    edges: [],
    nodeRefs: {},
  }),
```

Це очищає тільки `nodes` та `edges`. Коли додаватимемо інші сутності, розширимо функцію:

```
clearCanvas: () =>
  set({
    nodes: [],
    edges: [],
    zvts: [],
    zvtBranches: [],
    annotations: [],
    specificationTables: [],
    attachments: [],
    nodeRefs: {},
  }),
```

Важливо, щоб `clearCanvas()` очищала документні дані, але не видаляла методи Zustand.

## 3. CanvasController — оновлюємо openDocument()

```
export const openDocument = async (versionId) => {
  try {
    const response = await fetchData(
      `/api/documents/${versionId}/snapshot`,
      "GET"
    );

    // Snapshot відсутній — відкриваємо порожню схему
    if (response.exists === false) {
      useCanvasStore.getState().clearCanvas();

      return {
        success: true,
        empty: true,
        saveRevision: 0,
      };
    }

    // Snapshot існує — відновлюємо схему
    const snapshot = response.snapshot;

    if (!snapshot || !snapshot.elements) {
      throw new Error("Некоректна структура Snapshot");
    }

    useCanvasStore.setState({
      nodes: snapshot.elements.nodes ?? [],
      edges: snapshot.elements.edges ?? [],
      nodeRefs: {},
    });

    return {
      success: true,
      empty: false,
      saveRevision: response.saveRevision,
    };

  } catch (error) {
    console.error("Помилка відкриття документа:", error);
    throw error;
  }
};
```

Зверни увагу: на попередніх скріншотах ти використовував `buildSnapshot()` із власним форматом JSON. Якщо він повертає `snapshot.nodes` і `snapshot.edges`, а не `snapshot.elements.nodes`, потрібно використовувати саме ці поля. Не варто підлаштовувати існуючий Snapshot під умовну структуру прикладу.

## 5. Ще один важливий момент

Якщо користувач відкрив порожню схему, додав перший `node` і натиснув «Зберегти», API повинен створити перший запис у `DOC_SNAPSHOT` через `INSERT`.

Наступні збереження цього документа вже виконуватимуть `UPDATE` з перевіркою `SAVE_REVISION`.

Для початкового стану:

```
{
  exists: false,
  saveRevision: 0
}
```

Після першого успішного збереження:

```
{
  exists: true,
  saveRevision: 1
}
```

Моя рекомендація для твого редактора: зробити універсальний метод `resetDocumentState()` у Zustand. Він відповідатиме за очищення всіх об'єктів поточної схеми, а `openDocument()` вирішуватиме, викликати його для порожнього документа чи відновлювати дані із JSON.

Так ти уникнеш ситуації, коли користувач відкриває нову порожню схему, а на Canvas залишаються `nodes`, `edges` або ЗВТ з попереднього документа.
