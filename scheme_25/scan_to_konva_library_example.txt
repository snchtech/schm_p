ПЕРЕТВОРЕННЯ СКАНУ ПРОСТОЇ СХЕМИ НА JSON ГОТОВОЇ БІБЛІОТЕКИ NEXT.JS + KONVA

1. ПРИНЦИП
Не генерувати JSX зі скану. Розпізнати об'єкти, зіставити їх з ID бібліотеки, відновити геометрію/зв'язки і створити JSON для Zustand та Konva.

2. ПІДГОТУВАТИ КАТАЛОГ КОМПОНЕНТІВ
Кожен тип повинен мати стабільний typeId, версію, назву, шаблонні зображення (горизонтальна/вертикальна орієнтація), габарити, anchor points і допустимі повороти.
Приклад:
{
  "typeId": "valve_gate",
  "version": 1,
  "anchors": [{"id":"left","x":0,"y":20},{"id":"right","x":40,"y":20}],
  "size": {"width":40,"height":40},
  "allowedRotations": [0,90,180,270]
}
Реальні назви typeId та поля адаптувати до наявного store.

3. PIPELINE ДЛЯ ПРОСТОГО СКАНУ
A. Завантаження PNG/JPG або рендер PDF в PNG (300-600 dpi для дрібних символів).
B. Вирівнювання нахилу, обрізка, усунення шуму, адаптивна бінаризація (OpenCV).
C. OCR (PaddleOCR/Tesseract) -> текст, bounding boxes, confidence.
D. Пошук фігур: на першому етапі template matching OpenCV по відрендерених з Konva шаблонах з різними масштабами/поворотами. Якщо варіантів багато — навчений object detector (наприклад YOLO) на зразках власної бібліотеки.
E. Замаскувати знайдені фігури і текст; виявити прямі лінії (HoughLinesP / морфологія), об'єднати сегменти, знайти точки зламу та кінці.
F. Прив'язати кінці ліній до anchor points фігур з допуском, який масштабується відповідно до роздільності зображення. Не прив'язувати лише за близькістю, якщо є неоднозначність.
G. Відновити координати в системі полотна (scale, offset), нормалізувати орієнтації.
H. Побудувати JSON і перевірити його схему (Ajv), невідомі типи, конфлікти зв'язків, дублікати ID.
I. Показати preview поверх скану; користувач підтверджує/виправляє розпізнавання; після цього імпорт у Zustand.

4. ПРИКЛАД ВИХІДНОГО JSON (УМОВНИЙ ФОРМАТ)
{
  "nodes": [
    {"id":"n1","typeId":"valve_gate","x":62,"y":69,"rotation":0,"confidence":0.97},
    {"id":"n2","typeId":"valve_gate","x":170,"y":69,"rotation":0,"confidence":0.94},
    {"id":"n3","typeId":"valve_gate","x":278,"y":69,"rotation":0,"confidence":0.96}
  ],
  "edges": [
    {"id":"e1","from":{"nodeId":"n1","anchorId":"right"},"to":{"nodeId":"n2","anchorId":"left"},"points":[78,69,154,69]},
    {"id":"e2","from":{"nodeId":"n2","anchorId":"right"},"to":{"nodeId":"n3","anchorId":"left"},"points":[186,69,262,69]}
  ],
  "annotations": [
    {"id":"t1","text":"КР-1","x":62,"y":112},
    {"id":"t2","text":"КР-2","x":170,"y":112}
  ]
}
Важливо: координати тут ілюстративні. У справжньому імпорті вони обчислюються зі скану; id, anchors і формат edge мають відповідати реальним компонентам.

5. ІНТЕГРАЦІЯ
Next.js: форма завантаження, підкладка в Konva, preview з confidence, ручне виправлення, підтвердження.
Express API: POST /api/scheme-import/analyze (multipart), GET /api/scheme-import/:jobId, POST /api/scheme-import/:jobId/confirm.
Сервіс CV (доцільно Python + OpenCV + OCR, окремий контейнер): повертає лише структуровані detections і links. Node.js service трансформує у власний JSON і перевіряє.
Zustand: importRecognizedScheme(normalizedData) через єдиний адаптер; не записувати сирий JSON моделі напряму в store.
Oracle 21: зберігати затверджену схему через існуючий batch snapshot + indexed objects у транзакції. Оригінальний скан і дані confidence можна тримати як окремий імпортний артефакт для аудиту.

6. ДВА ПРАКТИЧНІ ВАРІАНТИ
Швидкий MVP без навчання: 5-15 стандартних типів, зображення шаблонів із Konva, OpenCV template matching, OCR, HoughLinesP, ручне підтвердження.
ШІ-варіант: передавати скан і каталог дозволених typeId мультимодальній моделі з вимогою структурованого JSON. Це швидкий прототип, але координати і зв'язки можуть бути помилковими. Для виробничої системи поєднати детектор символів + OCR + геометричний аналіз ліній + перевірку оператором. При великій кількості сканів навчити детектор на власних символах.

7. ЯК ЗРОБИТИ БІБЛІОТЕКУ ДЖЕРЕЛОМ ДАНИХ ДЛЯ РОЗПІЗНАВАННЯ
Автоматично рендерити кожен компонент у PNG на прозорому/білому фоні в кількох масштабах і поворотах; зберігати typeId, bbox, anchors, версію. Генерувати синтетичні схеми з випадковими розміщеннями, лініями, підписами, шумом, поворотом і якістю скану. Синтетика допомагає стартувати, але обов'язково тестувати на реальних паперових схемах.

8. КОНТРОЛЬ ЯКОСТІ
Вимірювати окремо: точність класифікації символів, похибку координат, якість OCR, правильність кінцевих зв'язків. Низька впевненість або неоднозначні anchors -> ручна перевірка. Ніколи не створювати зовнішній databaseId за здогадом моделі: відповідність до загального обладнання визначає користувач або окреме достовірне правило.

9. РЕКОМЕНДОВАНИЙ ПОРЯДОК
(1) Одна реальна схема, 2-3 типи елементів, 2 підписи.
(2) Експорт PNG-шаблонів з наявної бібліотеки.
(3) Розпізнавання фігур + OCR.
(4) Виявлення ліній і прив'язка до anchors.
(5) JSON adapter + Konva overlay + кнопка «Підтвердити імпорт».
(6) Тест на 20-50 реальних схемах, потім рішення про навчання моделі.

10. ПРАКТИЧНИЙ ВИСНОВОК
Для маленької стандартизованої схеми не потрібно відразу навчати нейромережу. Найшвидше почати з OpenCV + шаблонів з готових компонентів, OCR і редактора перевірки. Модель із зором корисна для початкового прототипу або складних символів, але її результат має проходити геометричну валідацію та підтвердження.
